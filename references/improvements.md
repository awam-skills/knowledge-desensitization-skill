# 待改进项

> 记录「已定稿、暂不做，但需改进」的设计缺口。每条给：**现状 / 为什么暂不做 / 改进方向 / 评估要点**。

## 1. 脱敏增量（暂不做）

**现状**

- 脱敏（`sanitize.py`）对**工作副本全量就地**执行：遍历全部文件、逐文件「读 → 替换 → 覆写」。
- 无「只处理本次改动文件」的能力；靠**幂等**（`TOKEN_RX` 保护区 + 迭代到不动点 + 稳定 HMAC token）
  保证「重复全量跑」不会产生二次污染 —— 所以现在跑全量是**安全但不省时**。
- **增量只存在于 `sync.py` 层**（真源 → 工作副本）：`size+mtime` 快判、必要时回退 `sha256`，
  只拷新增/改动文件；清单落 `<秘密材料根>/<id>/sync-manifest.json`。

**为什么暂不做**（用户 2026-10-22 定稿：待改进，暂时不做）

- 收益有限：知识库（如 Logseq）单次全量脱敏的绝对耗时不高；且**规则 / 字面量一旦变更，本来就该全量重跑**
  —— 增量反而可能漏扫「受新规则影响的历史文件」。
- 风险不容忽视：增量需要「某文件相对上次脱敏是否变化」的独立状态；一旦状态与实际不一致
  （改规则、改 exclude、回滚、跨机拷贝），会出现**漏脱敏** —— 比慢更危险。
- 幂等兜底已使「全量重跑」足够安全，暂不为省时而引入正确性风险。

**改进方向**（若日后要做）

- 复用 `sync-manifest.json` 的 sha256，建立 `<秘密材料根>/<id>/sanitize-state.json`（`rel → {sha256, mtime}`）。
- 增量模式：仅对「相对上次脱敏 新增/改动」的文件重跑；**规则文件**（`rules.json`、`literals.json`、
  `whitelist.json`、`exclude.json`）任一变化即**强制全量**。
- 保留 `--full` 随时全量重算；`--verify` 校验「增量结果 == 全量结果」。

**评估要点**（拍板前要回答）

- 单次全量耗时基线（源规模 × 文件数）实测值；
- 增量状态失效场景清单与「强制全量」触发条件是否完备；
- 漏脱敏的可检测性（`scan.py` / `probe.py` 能否兜住）。

## 2. 「见保险库」引用不可唯一逆映射（2026-10-23 发现并修复）

**缺陷（已修）**

- 旧引用「见保险库：<条目名>」按**条目名**逆映射；`sanitize.py` 生成的条目名不含 token 唯一片段，
  同文件、同标签的多个凭据同名。实测 `logseq-main`：`bw-items.json` **139 条只有 41 个唯一名**
  （21 组重名，其中 20 组对应不同 token）。
- 后果：`recover` 按名字反查只能取一个 token → 重名引用还原成错误明文；
  `recover --verify --source` 曾从 34/0 退化为 20/14。镜像本身仍安全（无明文），
  坏掉的是「逐字节可逆」这条核心不变量。

**修复（用户 2026-10-23 定稿：干净方案，不兼容旧引用）**

- 引用改为：`见保险库：<条目名> [vault:<label>:<hash8>]`。
  - `<条目名>` 保留人可读，与 Bitwarden 条目名逐字对应，便于网页端搜索。
  - `[vault:<label>:<hash8>]` 是**唯一主键**，等于 `map.json` 的 token 去掉 `REDACTED` 前缀；
    `recover` 直接按主键查 `map.json`，**不依赖条目名唯一性**，也不需要 `bw-items.json`。
- **不复用** `[REDACTED:...]` 作引用主键：否则 `backfill` 重跑会二次替换（不幂等），
  且会与镜像里保留的 PII 占位符混淆。
- `sanitize_lib` 把 `[vault:...]` 纳入保护区，重复脱敏不会误伤主键。
- 不做旧纯名字引用兼容：重跑 `sanitize --apply` + `backfill --apply` 后镜像内已无旧形态。

**实测（2026-10-23）**

- 临时 data-root 端到端：引用还原 137 处 / token 还原 130 处，源比对 **34 一致 / 0 不一致**。
- 正式 `logseq-main` 重生成后：**34 一致 / 0 不一致**；137 处引用全部带 `vault` 主键，旧形态 0。
- 连续第二次 `backfill`：替换 0 处，全镜像文件 sha256 不变。

**遗留（不影响可逆性）**

- Bitwarden 条目名仍可能重复（形如 `notes/<path> · <path> · <label>`），只影响人工辨识；
  若日后决定重导 Bitwarden，可再统一命名规则。
